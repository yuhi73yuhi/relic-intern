# Antigravity に渡すプロンプト（ここから下をすべてコピー）

---

あなたはプレゼン資料のデザイナー兼エンジニアです。インターンの最終発表で使うスライドを作成してください。

## 作ってほしいもの

- **形式**: ブラウザで開ける 1 ファイルの HTML スライド（`slides/index.html`）。外部ライブラリは CDN 読み込みのみ可（例: reveal.js）。
- **比率**: 16:9。←→キーでページ送り、`S` キーで発表者ノート表示。
- **枚数**: 14 枚前後。発表時間は約 7 分＋デモ 2 分を想定。
- **言語**: 日本語。フォントは Noto Sans JP（数値は等幅フォント）。
- **発表者ノート**: 各スライドに、話す内容を 2〜4 文で付ける。

## デザイン

プロダクトの UI に揃えた、DAW（音楽制作ソフト）風の洗練されたダークデザインにしてください。

- 背景 `#07090c`、パネル `#11161d`、文字 `#e4e4e7`、補足文字 `#7d8a97`
- アクセント: エメラルド `#10b981`（強調・良い結果）、シアン `#22d3ee`（お手本＝先生）、バイオレット `#a855f7`（自分＝生徒）
- 注意色: アンバー `#f59e0b`（惜しい）、ローズ `#f43f5e`（要改善）
- 1 スライド 1 メッセージ。文字は少なく大きく、数字は大きく見せる。箇条書きは最大 4 行
- 波形・グリッド線などの音楽的なモチーフを控えめに使う
- アプリの画面写真は `groovelens/screenshot.png`（縦長の全画面キャプチャ）にあります。デモ・機能紹介のスライドでは、この画像の必要な部分だけを切り出して（CSS の `object-position` などで）使ってください

## 守ってほしいこと

- 下の「スライド構成」にない数値や実績を勝手に作らない（市場規模・ユーザー数などを捏造しない）
- 精度検証の数値は **合成音とスマホ録音シミュレーションによる検証** であることを必ず小さく注記する
- 課金額・施策は「アイデア／仮説」として表現する

## スライド構成

### 1. タイトル
- **GrooveLens（グルーヴレンズ）**
- サブタイトル: 「なんかダサい」の正体を、0.01秒単位で可視化する
- 発表者名: 【氏名】／ Relic インターン最終発表

### 2. 解決したい課題
- 「楽譜通りに弾けているのに、録音して聴くとなんかダサい（機械的・素人っぽい）」——中級者プレイヤーの壁
- 音楽の「ノリ（グルーヴ）」は感覚的で言語化できない → 独学では何が悪いのか分からず挫折する
- 音楽教室の講師も「もっとタメて」と感覚でしか指導できない

### 3. 原体験
- 半自動の楽器演奏ロボットの研究で、**正確に弾かせても全く心地よくない**という壁に直面
- 0.01秒単位の微細なズレこそが「心地よさ」の正体だと気づいた
- ビジュアル案: 機械的に揃ったグリッド上の音符と、少しずつズレた人間の演奏を対比する図

### 4. ターゲット
2 カラムで表示。
- **C 向け**: 軽音サークル所属者や「弾いてみた」投稿者など、演奏クオリティを上げたい独学の中級プレイヤー（ギター・ベース・ボーカル等）
- **B 向け**: 生徒の継続率を上げたい・オンライン指導の質を高めたい音楽教室の講師

### 5. プロダクト概要
- **GrooveLens**: お手本と自分の演奏をスマホで録音すると、「どこが・何が・どれだけ」惜しいのかが並べて見える Web アプリ
- ドラム・ベース・ギター・ピアノ・ボーカルに対応。楽器×ジャンル（ファンク・ロック・ジャズ等）ごとに判定の基準を固定
- グルーヴ一致度スコア（0〜100点）と、具体的な改善アドバイスを自動生成
- ブラウザだけで解析が完結（音声はサーバーに送らない）

### 6. デモ（ここで実演）
- 大きく「LIVE DEMO」と表示し、画面写真を背景に薄く敷く
- 発表者ノートにデモの手順を書く:
  1. 楽器「ドラム」×ジャンル「ファンク」を選び「デモ音源をロード」
  2. スコア 78点 と「惜しいポイント」を見せる（「2・4拍目が平均 27ms 早い（8回中8回）→ 直すと +6点」）
  3. 波形の比較で、1音ごとのズレを見せる
  4. ニュアンス・マップで、タイミング以外（強弱・アタック・音の長さ）も見えることを示す
  5. ノート詳細で音の形を重ねて表示し、「交互に聴く」で耳でも比較
  6. 「上位3つを直すと 78 → 92点」で締める

### 7. 主な機能（画面写真＋3 つの吹き出し）
- **惜しいポイント**: 直すと上がる点数の順に、場所・ズレの量・練習方法を提示
  例:「全体的に走り気味。2・4拍目をあと 0.03秒タメるとグルーヴが出ます」
- **ニュアンス・マップ**: 1音ごとに タイミング／強弱／アタック／音の長さ（ボーカルはピッチも）を色分け
- **先生比 と メトロノーム比**: メトロノーム基準では -10ms で「OK」でも、先生の意図的なタメと比べると -27ms。既存アプリでは見つからないズレを発見

### 8. 既存アプリとの違い（比較表）
| | 既存のリズム練習アプリ | GrooveLens |
| --- | --- | --- |
| 比較の基準 | メトロノーム（機械的なグリッド） | お手本の演奏（意図的なタメを含む） |
| 見るもの | タイミングのみ | タイミング・強弱・アタック・音の長さ・ピッチ |
| 出力 | 合っている／ズレている | どこが・何が・どれだけ・直すと何点上がるか |

### 9. 技術の裏付け：スマホ録音でも 0.01秒 を測れるか
- 正解が分かっている演奏に「スマホ内蔵マイク相当の劣化」（低音カット・部屋の反響・自動音量調整・雑音・録音開始の遅れ）を加えて精度を検証
- 結果（95% の音での誤差）を棒グラフで表示し、10ms のラインを引く:
  - ドラム × ファンク ≤1.2ms ／ ベース × ファンク ≤1.9ms ／ ギター × ファンク ≤2.0ms → **十分**
  - ピアノ × ポップス ≤5.2ms ／ ボーカル × バラード ≤5.3ms → 条件付き
  - ボーカル × ポップス ≤10.8ms → 精度不足
- メッセージ: **リズム楽器は 10ms 単位の判定に十分 → まずはリズム楽器から提供**
- 注記: ※合成音とシミュレーションによる検証。実機スマホでの検証は今後実施

### 10. マネタイズ
2 カラムで表示。
- **BtoC（フリーミアム）**: 基本のタイミング解析は無料。権利処理済みのお手本ライブラリとの詳細比較や、AI によるパート別改善アドバイスを月額課金（例: 月額 980円）
- **BtoB（音楽教室向け SaaS）**: 講師が生徒の宿題（録音データ）を定量評価・成長管理できるダッシュボードを、教室単位の月額ライセンスで提供（生徒の退会率低下に貢献）
  - 講師がお手本を 1 回録れば、生徒は家で何度でも比較できる → 週 1 回のレッスンの価値が残りの 6 日にも届く

### 11. SNS マーケティング
- **施策**: 「グルーヴ一致度スコア」と「波形比較カード」を、ワンタップで X / TikTok / Instagram にシェア
- **投稿イメージ**（SNS 投稿風のカードで表示）:「〇〇のベースライン、お手本とのグルーヴ一致度 92点出た！あと 0.02秒タメれば完璧… #GrooveLens」
- **意図**: 楽器プレイヤーは「練習の成果を見てもらいたい・承認されたい」欲求が強い。「弾いてみた動画」にスコアと波形を重ねて視覚的なエンタメ性を生み、学生プレイヤーやインフルエンサーの自発的な拡散（UGC）で、広告費を抑えて認知を広げる

### 12. 事前フィードバックを受けての変更
3 つのフィードバック → 対応 を矢印でつなぐ図にする。
- **① 技術の前提**（スマホ録音から 0.01秒 の差やアタック・減衰の違いを安定して取り出せるか）
  → スマホ録音シミュレーションで精度を検証する機能を実装。リズム楽器は誤差 3ms 以内と確認し、提供はリズム楽器から始める
- **② 比較対象**（市販音源は権利処理と、他の楽器の音を分ける技術的な難しさがある）
  → お手本は講師やお手本奏者が録音した「楽器 1 本だけの演奏」を使う方式に変更。市販音源を使わないので、権利処理も音の分離も不要
- **③ 既存アプリとの違い**（「タイミング以外のニュアンスまで分かる」ことを強みに）
  → タイミングに加えて強弱・アタック・音の長さ・ピッチまで 1 音ずつ比較し、「どこが惜しいのか」を点数付きで示す画面に
- **ジャンルによってノリが違う**
  → 楽器×ジャンルのプロファイルを作り、ジャンルごとに判定の物差し（例: ファンク ±10ms、ジャズはスウィング比）を固定

### 13. あえて採用しなかった提案と、残る課題
- **あえて採用しなかった提案**: 「楽器を 1 つに絞る」
  → C 向けのターゲットは楽器がバラバラなため、複数楽器の対応は残した。そのかわり、楽器×ジャンルごとに基準を固定して比較の基準がぶれないようにし、提供の順番は精度検証の結果（リズム楽器が先）で決める
- **残る課題**
  1. 継続利用の検証: お金を払って使い続けてくれるか（三日坊主にならないか）は未実証 → 大学の軽音サークルや知り合いの奏者に触ってもらい、定性ヒアリングを行う
  2. 実機での精度: 今回は合成音とシミュレーションでの検証。実際のスマホ・楽器での検証と、ボーカルの精度改善が必要
  3. 基準データ: 楽器・ジャンルごとの「良いグルーヴ」の基準を、講師と一緒に作り込む必要がある

### 14. 今後の展望
タイムライン（3 ステップ）で表示。
1. 大学の軽音サークルや楽器コミュニティに β 版を配布し、「スコア化で上達を実感できるか・継続するか」を検証
2. SNS シェア機能で C 向けユーザーを増やす
